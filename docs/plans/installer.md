# План: установщики Axel' «для людей»

Цель: игрок открывает страницу релиза или README, видит одну понятную ссылку для своей системы,
скачивает один файл и ставит его привычным способом, на своём языке. Ничего не компилирует,
не выбирает между архитектурами и не разбирается в `.app.tar.gz`.

Сейчас (rc.4): 9 файлов с техническими именами, два `.dmg` (Apple Silicon / Intel), установщик
Windows на английском, стандартное серое окно `.dmg`, описание релиза без таблицы «какой файл».

Без сертификатов разработчика (решение владельца 21.10.2026) остаются предупреждения
Windows SmartScreen и macOS Gatekeeper — их не убрать, только понятно объяснить.

## Решения (предлагаются, нужен ответ владельца — отмечены «?»)

| # | Решение | Почему |
|---|---|---|
| Р1 | macOS — один универсальный `.dmg` (Apple Silicon + Intel в одном приложении) | не нужно знать, какой у тебя процессор; цена — файл примерно вдвое больше (~20 МБ) |
| Р2 | Windows — только установщик `.exe` (NSIS); `.msi` не выкладываем ? | `.msi` нужен администраторам для массовой установки; игроку — лишний выбор |
| Р3 | Не выкладываем `.app.tar.gz` | это файлы для автообновления, которого у нас нет |
| Р4 | Имена файлов без версии: `Axel-Launcher-Windows.exe`, `Axel-Launcher-macOS.dmg`, `Axel-Launcher-Linux.deb/.rpm/.AppImage` | на них работают постоянные ссылки `releases/latest/download/…` — «Скачать» из README всегда даёт свежую версию |
| Р5 | Установка Windows — для текущего пользователя, без прав администратора; ярлыки на рабочем столе и в «Пуске» | как у игровых лаунчеров; не нужен пароль администратора |
| Р6 | Удаление программы не трогает миры и профили (`~/.quarry`) ? | миры игрока важнее чистоты диска; в окне удаления пишем, где лежат данные и как их убрать вручную |
| Р7 | Установщик Windows на русском и английском, язык выбирается при запуске (по умолчанию — язык системы) | |

## Дизайн

Общее: тёмная мята лаунчера (`--bg #0b1110`, `--panel #121b19`, `--accent #52d6a0`, текст `#eaf2ed`,
второй текст `#a2b5ac`), шрифт IBM Plex Sans, значок-аксолотль из `ui/src-tauri/icons`.
Никаких градиентов и теней — как в самом лаунчере. Текст на картинках — по-русски и строкой
ниже по-английски (Windows и macOS не меняют картинку под язык).

**macOS, окно `.dmg`** (660 × 400 точек, фон в двух размерах: 660 × 400 и @2x 1320 × 800):
- слева значок Axel Launcher (128 pt), справа ярлык «Программы»; между ними пунктирная мятная
  стрелка;
- внизу крупно «Перетащите Axel' в «Программы»», мельче «Drag Axel' to Applications»;
- размер окна и позиции значков задаются в `tauri.conf.json` (`bundle.macOS.dmg`:
  `background`, `windowSize`, `appPosition`, `applicationFolderPosition`).

**Windows, мастер установки (NSIS):**
- окно выбора языка → «Добро пожаловать» → папка (по умолчанию в профиле пользователя) →
  установка → «Готово» с галочкой «Запустить Axel'»;
- боковая картинка 164 × 314 (BMP, 24 бита): тёмная мята, значок аксолотля, подпись «Открытый
  лаунчер Minecraft: Java Edition»;
- картинка шапки 150 × 57 (BMP): значок на светлом фоне (шапка NSIS всегда светлая);
- значок самого установщика — значок лаунчера;
- текст первой страницы: куда ставится, что права администратора не нужны, что миры и
  профили хранятся отдельно и не пропадут при удалении.

**Страница релиза** (текст в `release.yml`): таблица «Ваша система → файл», затем коротко
«что делать, если система предупредила» для Windows и macOS, ссылка на подробную установку.

**README:** блок «Скачать» в самом верху — три ссылки «Windows», «macOS», «Linux» на
`releases/latest/download/<файл>`; таблица и инструкции — в разделе «Установка».

## Чего не делаем

- Подпись сертификатами Apple и Microsoft, нотаризация — решение владельца (нет сертификатов).
- Автообновление — решение владельца; лаунчер сообщает о версии и открывает страницу релиза.
- Свой веб-сайт со скачиванием — владелец сайтами не занимается; хватает GitHub.
- Портативная версия Windows (zip без установки) — по запросу.

## Риски и что проверить

- `assetNamePattern` в tauri-action — проверить по документации используемой версии до правки.
- Универсальная сборка macOS требует обе цели Rust (`aarch64`, `x86_64`) и вдвое дольше собирается.
- Постоянные ссылки `releases/latest/download/…` не видят pre-release: до публикации 0.1.0 они не работают — проверить можно только после релиза.
- Картинки NSIS должны быть BMP, иначе сборка Windows упадёт — проверится только в CI на rc.5.

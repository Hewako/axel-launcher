# План разработки: установщики и скачивание Axel'

Рабочий план Claude по всем 27 пунктам (решение владельца 21.11.2026: «делаем всё»).
Дизайн (картинки установщиков, лента обновления в лаунчере, кнопки в README) рисует владелец —
техзадание в `docs/plans/installer-design.md`. Пока картинок нет, всё работает со стандартным
видом; картинки подключаются отдельными задачами в конце.

Правила работы: ветка `stage-17-release`; код читается и правится через граф (`graphify
query/explain`, после правок `graphify update .`); каждая задача — отдельный коммит по-русски;
проверки `cargo fmt/clippy/test`, `tsc`, `npm run i18n:check`, `ipc:check`, `build`; push,
слияние в main и теги — только с согласия владельца.

Цель: игрок видит понятную ссылку для своей системы, скачивает один файл и ставит его
привычным способом, на своём языке; ничего не компилирует и не выбирает между архитектурами.

## Решения владельца

- 21.10.2026: без сертификатов разработчика, без автообновления, релизы публикует владелец.
- 21.11.2026: один `.dmg` для любых Mac; в Windows только `.exe`; удаление программы не трогает
  миры и профили (`~/.quarry`); картинки рисует владелец; делаем все 27 пунктов.

## Как будет у игрока (итог)

| Система | Файл | Установка |
|---|---|---|
| Windows 10 и 11, в том числе на ARM (через эмуляцию) | `Axel-Launcher-Windows.exe` | мастер на русском или английском, без прав администратора, ярлыки |
| Windows, без установки | `Axel-Launcher-Windows-portable.zip` | распаковать и запустить |
| macOS 11 и новее, любой Mac | `Axel-Launcher-macOS.dmg` | перетащить в «Программы» |
| Ubuntu, Debian, Mint | `Axel-Launcher-Linux.deb` | двойной клик или `sudo apt install ./…` |
| Fedora, openSUSE | `Axel-Launcher-Linux.rpm` | `sudo dnf install ./…` |
| Любой другой Linux | `Axel-Launcher-Linux.AppImage` | разрешить запуск; на Ubuntu 22.04+ нужен `libfuse2` |
| — | `SHA256SUMS.txt` | контрольные суммы всех файлов |

Данные игрока — всегда в `~/.quarry` (`%USERPROFILE%\.quarry` на Windows); ни обновление,
ни удаление программы их не трогают.

## Список проверки владельцем (войдёт в RELEASE_CHECKLIST)

Windows 10 или 11:
1. Если стояла пробная версия через `.msi` — удалить в «Параметры → Приложения».
2. Скачать `Axel-Launcher-Windows.exe`, запустить; SmartScreen — «Подробнее» → «Выполнить в любом случае».
3. Окно языка: выбран язык системы, все страницы на выбранном языке.
4. Папка по умолчанию в профиле пользователя, пароль администратора не спросили.
5. Ярлыки на рабочем столе и в «Пуске»; галочка «Запустить Axel'» работает.
6. Лаунчер открывается, вход Microsoft, профиль, игра до главного меню.
7. Удаление: окно говорит про `%USERPROFILE%\.quarry`; после удаления папка на месте.
8. Portable-zip: распаковать в любую папку, запустить `Axel Launcher.exe` — открывается.

Linux:
1. `.deb`: установка, значок в меню приложений, запуск.
2. AppImage на Ubuntu: без `libfuse2` — что видно; с ним — запускается.
3. Вход, профиль, игра до главного меню.

## Риски и что проверить по ходу

- `assetNamePattern` в tauri-action — сверить с документацией до правки (1.3).
- Ярлык на рабочем столе и свои строки в окнах NSIS — как именно их даёт шаблон Tauri используемой версии (2.3, 2.4).
- Значок образа `.dmg` — есть ли настройка в Tauri (3.2).
- Универсальная сборка macOS собирается дольше; суммы и проверка файлов — отдельная задача после всей матрицы.
- Постоянные ссылки `releases/latest/download/…` не видят пре-релизы: проверяются только после публикации 0.1.0.
- Portable без установщика не поставит WebView2 сам — на Windows 10 без него не запустится; это сказано в `README-portable.txt`.
- Картинки NSIS — только BMP 24 бита, иначе упадёт сборка Windows (проверится в CI).

# Распространение Axel': заготовки

Всё здесь — на после выхода 0.1.0: каталоги принимают только опубликованные (не пробные) версии.
Ссылки в манифестах ведут на файлы конкретной версии (`releases/download/vX.Y.Z/…`), суммы —
из `SHA256SUMS.txt` этого релиза. Имена файлов задаёт `.github/workflows/release.yml`.

## winget (Windows) — `winget/`

Три файла манифеста для `microsoft/winget-pkgs`. Установщик NSIS (`nullsoft`), ставится в
папку пользователя (`Scope: user`), тихая установка — `/S`, её winget передаёт сам.

Владельцу: заменить `VERSION` и `SHA256`, на Windows проверить `winget validate` и
`winget install --manifest`, затем отправить PR в `microsoft/winget-pkgs` со своего аккаунта
(проще всего через `wingetcreate submit`). Их автоматическая проверка запускает установщик в
песочнице; неподписанный `.exe` допускается, но SmartScreen/антивирус в проверке может
задержать PR — тогда поможет подпись (ниже).

## Homebrew (macOS) — `homebrew/axel-launcher.rb`

Cask для своего tap. В основной каталог Homebrew молодые проекты не берут (нужна известность),
а неподписанные приложения туда больше не принимают вовсе, поэтому — свой tap.

Владельцу: создать публичный репозиторий `Hewako/homebrew-tap`, положить файл в
`Casks/axel-launcher.rb`, заменить `VERSION` и `SHA256`. Игрок ставит
`brew install --cask hewako/tap/axel-launcher`. Предупреждение Gatekeeper остаётся (приложение
не нотаризовано) — это сказано в `caveats`.

## SignPath Foundation (подпись `.exe` для Windows)

Бесплатная подпись для открытых проектов; убирает предупреждение SmartScreen не сразу, а по мере
набора репутации у сертификата. Условия (прочитано на signpath.org 21.11.2026):

- лицензия OSI без коммерческой двойной лицензии — GPL-3.0 подходит; весь подписываемый код —
  свой или открытый;
- сборка из исходников проверяемым способом (CI из репозитория), каждый релиз подписи
  подтверждается вручную;
- в файлах заданы название и версия продукта (Tauri это делает);
- на странице проекта — раздел «Code signing policy»: текст про SignPath, роли команды (авторы,
  проверяющие, утверждающие) со ссылками, заявление о приватности (есть в README);
- у всех участников — двухфакторная защита аккаунта;
- проект уже выпущен в том виде, который подписывается, поддерживается и описан; возраст не
  оговорён, но SignPath проверяет репутацию и может отказать.

Что поменяется в `release.yml`: после сборки `.exe` — шаг отправки файла на подпись (их
действие для GitHub Actions) и ожидание подтверждения; суммы считаются уже по подписанному
файлу (`finalize` это и так делает после сборок). Точный шаг — по их документации после
одобрения заявки. Заявку подаёт владелец (кнопка Apply на signpath.org) после 0.1.0; от Claude —
раздел «Code signing policy» в README и правка `release.yml`.

## Flathub (Linux) — оценка, решение за владельцем

Объём заметный, поэтому пока не начато:

- Flathub собирает только из исходников и без сети: все зависимости Rust и npm надо заранее
  описать в манифесте (генераторы `flatpak-cargo-generator` и `flatpak-node-generator`),
  при каждом обновлении зависимостей — пересобирать эти списки;
- песочница: Axel' хранит данные в `~/.quarry` и скачивает Java и игру туда же — нужно либо
  разрешение `--persist=.quarry`, либо перенос данных в папку Flatpak; вход Microsoft через
  системное хранилище паролей работает через портал Secret;
- ревью Flathub требует AppStream-описания (`metainfo.xml`) со скриншотами и значка, и проверяет
  каждое разрешение песочницы;
- выпуск каждой версии — отдельный PR в репозиторий приложения на Flathub.

Оценка: 1–2 дня работы и одно-два ревью. Для 0.1 хватает `.deb`, `.rpm` и AppImage;
к Flathub разумно вернуться, когда появятся игроки на Linux, которые попросят.
